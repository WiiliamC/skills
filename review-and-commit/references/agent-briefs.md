# 子代理交接范本

按本次任务填入实际路径与约束，避免继承无关对话。独立 review 每轮使用新代理；需要补证可继续使用本轮代理。主 agent 保留简短的复核结论，不搬回完整 diff 或提示词。

## Review

```text
你是本轮唯一的 review subagent，不再委派。
仓库与允许读取范围：<绝对路径>
审查口径：<changes，或 branch + 固定 merge-base SHA；补充用户限定文件>
需求、验收标准和约束：<事实；未知之处标明>
前轮结论：<已解决问题、已驳回建议及理由；有新证据可重新提出>
读取 <review-changes 目录>/references/review-workflow.md 及其引用的规则。
完成缺陷和保持功能的简化审查；改变功能范围的建议单独标明。
只读，不修改、格式化、暂存、提交或发布评论；验证遵守目标仓库权限与指令。
记录起始 HEAD、实际范围及阅读内容；以实际 diff 和文件内容复核变化，不计算自定义指纹（覆盖参考流程中的可选指纹方式）。内容变化时重新核实受影响部分，无法完成则报告审查未完成。
返回紧凑中文报告：范围与完整性、缺陷、简化建议、证据和位置、实际验证及限制。
进度仅简短回报，不返回原始 diff 或大段工具输出。
```

## Fix

```text
你是本轮唯一的 fix subagent，不再委派。
仓库：<绝对路径>；允许修改：<明确的目录或文件边界>。
需求与必须保留的契约：<确认的目标、约束和用户已有改动>
主 agent 已确认的问题：<逐项证据、触发条件、修复目标>
不实施已驳回项：<建议及理由>。
仅修复上述问题和必要关联调整；不要扩大需求或覆盖其他改动。
读取适用仓库指令，执行与修复匹配的必要验证和仓库要求的格式化。
不暂存、不提交、不推送；需要权限时按环境机制处理，不绕过限制。
返回最终修改摘要、问题对应结果、实际验证及限制；等待会写文件的工具完成后再交回。
```
