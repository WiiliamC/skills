# 完整改动审查

主 agent 只负责交接与呈现，审查由一个独立 sub-agent 完成。详细规则和代码留在子代理上下文；最终报告仍会进入主 agent 上下文，不能承诺零上下文占用。

## 主 agent：轻量交接

1. 从用户请求和已有上下文确定仓库路径、目标（PR / 分支 / commit / 未提交改动）、指定基线、需求与仍有效的限制。不在主上下文展开 diff、官方提示词或详细审查流程；缺少路径时只做必要的定位。基线和 PR 实际 base/head 可由子代理查明。
2. 使用委派工具启动一个 sub-agent。支持 `fork_turns` 时设为 `"none"`，通过任务简报显式传入必要信息，不继承完整对话。沿用当前模型，不固定模型或推理档位。
3. 要求子代理读取本目录的 [审查流程](references/review-workflow.md)，自行读取其中引用的规则和目标仓库的适用指令，完成只读审查，不再委派。传入相关用户约束和授权边界，尤其是未保存到仓库文件的要求。
4. 等待期间保持沟通；只转述简短进度，避免把中间 diff、候选 findings 或工具输出搬回主上下文。子代理存在关键事实缺口时，帮助补充或向用户澄清。
5. 收到最终报告后直接呈现，保留具体证据、位置、优先级与验证限制。主 agent 不重复完整审查，不把“未发现缺陷”强化成正确性保证。只有明显遗漏或内部矛盾才交回同一子代理复核。

任务简报示例（替换实际路径和目标）：

```text
你是本次完整 review 的唯一审查代理。
仓库：<绝对路径>
审查目标：<PR 链接 / 分支及基线 / commit / 未提交改动>
需求与用户约束：<与本次改动有关的事实和限制；未知的明确标记>
读取 <skill目录>/references/review-workflow.md 并完成全部流程。
默认只读；不修改目标文件、不暂存、不提交、不推送、不发布 PR 评论；不再委派。
自行获取 diff 和必要上下文。进度只回传一句话；最终回传完整且紧凑的报告。
```

## 委派边界

- 本 skill 明确要求使用独立子代理，授权本次审查委派；不授权修改或外部发布。用户后续要求修复时，另行执行相应实施流程。
- 委派工具不可用或被环境禁止时，说明无法满足独立上下文要求；不自动退回主 agent 完整审查。返回限制，并由用户选择是否接受主 agent 执行。
- 环境不支持空历史 fork 时，只传递最少必要信息，并说明上下文隔离限制；不声称启动子代理能移除主 agent 已有上下文。
- 审查依赖相邻的 `simplify-changes/SKILL.md`。子代理负责检查依赖；缺失时报告简化阶段未完成，不静默跳过或临时改写依赖。
