# 仓库文档维护

先确定目标仓库，读取适用的 `AGENTS.md`、README、文档入口及相关已有文档。项目路径从目标仓库解析，不能从全局 skill 的位置推导。沿用项目约定和合理现有结构，仅维护当前任务涉及范围。

## 分类与位置

以用途分类，项目约定优先；没有约定时按需采用以下默认位置，不预建空目录、不强制迁移现有结构。

| 内容 | 默认位置 | 内容边界 |
|---|---|---|
| 开发记录 | `docs/development/YYYY-MM/<topic>.md` | 需求、实现、修复、验证、验收与遗留问题 |
| 实验报告 | `docs/experiments/<topic>.md` | 实际实验的方法、比较条件、结果、证据和局限 |
| 工程基准 | `docs/benchmarks/<topic>.md` | 吞吐、延迟、资源占用及工程比较 |
| 技术调研 | `docs/research/<topic>.md` | 引用事实、适用性、候选方案和待验证判断 |
| 计划 | `docs/plans/<topic>.md` | 待实施方案或待运行协议 |
| 设计与使用 | 代码旁 README 或已有设计文档 | 当前接口、数据契约、操作方式 |

新主题名默认小写英文和下划线；已有命名按项目保持。明确调用的工作流若指定单次变更日志，则沿用该日志，不再生成重复开发记录。长期维护规则放最近适用的 `AGENTS.md`，当前用法与接口放 README 或已链接的设计文档。

实现完成、测试通过、有数值或 smoke 跑通都不证明实验效果。未运行实验的实现归开发记录，待运行协议标为计划；负面结果属于实验。工程测速归基准，正式实验的辅助耗时可随报告保留。结果校验、输入指纹、完整性检查和独立复算是证据，不能作为开发测试细节从报告中删走。

## 维护流程

1. 阅读相关文档、变更和实际结果来源，区分当前默认、历史运行及待执行方案，不从可变配置反推历史结果。
2. 按用途选择位置；混写时按语义完整的段落或小节拆分，保留方法、结果、证据和限制。窄范围编辑不扩大为全仓整理。
3. 开发记录使用实际事件日期，说明目标、关键决策、验证、遗留问题和已知关联提交。未知日期或提交如实标记，不用迁移时间或当前 HEAD 替代。按事件月份归档为无项目约定时的默认方式。
4. 实验报告读取 [实验报告证据规则](references/experiment-reports.md)。基准记录环境、比较条件、计时边界、重复次数和局限；调研区分引用事实与项目判断；计划标记待实施状态；设计及 README 描述当前契约。
5. 详细历史只维护一份，其他文档链接引用。产物沿用项目资产位置，不因整理文档复制、重算或提交。项目无约定时先查实际来源，不假设固定日志或训练输出目录。

## 历史与迁移保护

保留原指标、日期、样本数、数据划分、版本、代码及模型来源、实际协议、结论与限制。不能把旧结果重标为当前版本，不能从开发测试推断业务或模型效果。

修正错误时记录修订日期、依据和影响，保留可追溯的原口径；指标定义或方法变更明确标注，不把不同定义直接排名。中断、重跑、排除条件及来源变化若影响结果，应留在报告中。

迁移前保留源内容用于比对并尊重用户改动；迁移后核对数据和限制说明，修复引用及章节锚点，避免留下重复详细记录。重算 Markdown 相对链接，但代码块中从仓库根运行的命令路径不因文档搬迁自动改写。

历史记录中的命令和配置按事件日期解释，当前指南独立维护。区分原有本地产物不可用与迁移新增断链，不承诺每个 checkout 都能访问历史产物。

## 验收

检查分类、日期、完成状态和事实依据；核对迁移前后的关键数据、表格、来源、负面结论和排除条件。检查新增引用、锚点和旧文件名引用，确认汇总与正文一致。

遵循项目的 Git/LFS 状态检查约定；存在 LFS 时区分环境限制和实际内容变化，不把过滤器错误当作文件损坏。纯文档整理不要求训练、测速或全仓测试，不自动提交或修改业务代码。
