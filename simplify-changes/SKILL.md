# 改动简化

以仓库 owner 的视角缩小改动、降低维护成本。减少行数是结果，不以牺牲功能、性能或可验证性换取数字。

## 确定范围与模式

- “检查有没有能简化的部分”“只读审查”：只分析并给建议，不修改文件。
- “简化这些改动”“实施第几项”“让 subagent 修改，你验收”：实施已授权的简化，不停在建议。
- 按最新明确指令判断模式。用户明确结束只读并授权修改后，进入实施模式；仍有效的限制继续遵守。确有歧义时先做不依赖答案的只读检查，再澄清。
- 简化授权涵盖保持行为的局部重构；删除仍使用的功能、改变兼容性或拆分提交历史须有相应授权。不要把功能削减混入重构。
- 遵循目标仓库的 `AGENTS.md`、测试入口和现有设计。此 skill 对任意仓库适用，不复制某个项目的路径、环境或算法约束。

先明确目标版本和比较口径：

| 用户目标 | 检查范围 |
|---|---|
| PR | PR 实际 base/head 及完整 diff；不假设当前 checkout 就是该 PR |
| 当前分支相对某基线 | 用 merge-base 比较该基线与 HEAD；基线按用户或仓库事实确定 |
| 未提交改动 | HEAD 到工作区的全部 tracked diff，包含 staged/unstaged，并检查相关 untracked 文件 |
| 当前分支全部改动 | 分支 diff 加当前工作区改动；明确记录两部分，避免漏掉未提交实现 |

记录开始时的工作区状态、涉及文件、增加/删除行数及相关测试。已有用户改动是输入，不覆盖、不重置、不擅自暂存。仓库有 Git LFS、生成物或 fixture 噪声时，按本地规则检查并区分真实改动。

## 建立简化清单

先看 diff 范围和功能入口，再读相邻实现、测试及文档。优先检查新增或修改的代码，扩展阅读仅为确认调用和契约。

按证据和收益排序：

1. **被替代的旧链路**：已换用新入口，但旧实现、配置、专属测试仍存在。
2. **重复责任**：相同流程或校验散落多处，业务层绕回 CLI，调用者被迫了解内部细节。
3. **过度设计**：当前范围没有实际使用的抽象、模式、配置层或兼容路径。
4. **重复测试和文档**：仅维护旧契约的测试，重复说明；保留实际行为验证和必要出处。
5. **交付范围扩张**：基准工具、研究资料、独立修复或加速功能可以单独审查；作为范围建议，不自行删除仍有用途的功能。

判定死代码必须追踪生产入口和仓库引用，包括公共导出、注册表、配置字符串、插件加载、脚本和文档使用。没有静态调用不等于无人使用；识别动态加载或外部 API 风险。测试是唯一调用者时，区分旧功能专属测试和仍有效的底层契约。

每项给出具体位置、调用证据、建议操作、必须保留的行为、风险和合理净减估算。区分“保留功能的简化”和“减少交付范围”；不要把代码搬迁、文件合并或压缩格式计作消除复杂度。

避免为减少几行引入通用基类、巨大模块、多模式返回协议或新的继承体系。独立且内聚的小类文件可以保留。共同外形相似、实际语义不同的路径不强行统一。

## 实施与分工

实施模式下，直接完成已授权且有证据的简化；审查模式下，到具体建议和收益估算为止。

当委派工具可用、环境允许委派且用户未要求亲自实施时，优先由**一个 subagent 修改、主 agent 验收**；委派不可用时自行实施并完成相同验收。仅因使用本 skill 不再引入额外代理或固定模型要求。

主 agent 先收敛可执行范围，再给实施代理任务简报：目标 diff、允许修改的文件、具体简化项、必须保留的契约、测试入口和现有用户改动。要求不再委派、不提交，报告实际修改和已运行的检查。主 agent 不同时编辑同一批文件，可独立检查调用关系和准备验收。

删除旧链路时同步清理失效导入、配置和说明。混合测试只删过时断言；保留仍有效的场景，必要时用受控输入代替被删除的求解器。

提取共同逻辑时逐项检查实际契约，按相关性选择：

- 输入精度、求值顺序、边界判定、输出结构、默认值和错误传播。
- 子类、注入函数、自定义 tracer 等扩展点的原调用方式；不擅自增加 kwargs 或暴露原先被丢弃的返回值。
- 缓存键、可变状态、内存上限、流式/分批处理和并行顺序。
- 原子发布、续跑、来源/筛选指纹和数据完整性。
- 加速路径与参考回退、进程池生命周期，以及性能测量包含的启动/退出开销。

保持这些行为比统一所有代码路径更重要。性能未测量时，不声称重构保持吞吐或实现提速。

## 主 agent 验收

独立查看最终 diff，不把 subagent 的“完成”当成验收结果：

- 所有删除有引用证据，仍使用的逻辑和测试未被误删；目标范围之外没有顺手清理。
- 提取后依赖方向清晰，没有循环依赖或把重复代码搬到更复杂的协议中。
- 对照原代码检查参数、返回值、扩展点、异常、缓存及生命周期，而非只看 happy path。
- 运行仓库提供的相关测试和必要静态检查。优先复用已有契约测试；新增测试用于真实回归风险，不镜像实现。实施代理和主 agent 协调检查，避免无变化地重复全部测试。
- GPU、外部服务或其他必要条件不可用时，保留可在本地运行的分发/回退测试，如实报告未验证部分；依环境规则检查设备或申请权限，不以 sandbox 的不可见判定设备不存在。
- 发现问题后修正，并仅针对新修改、失败或未解决风险补跑检查。最后检查残留引用、diff 格式及工作区范围。

用相同口径重新统计文件和增删行数，计算实际净减；区分目标 diff 的最终规模与本轮简化自身 diff。生成物和 binary 不用文本行数衡量。不能只报删除行数而忽略新接口及回归测试的增加。

最终简短报告：完成的简化、实际净減、验证结果及未验证限制。审查模式使用明确的估算；实施模式报告实测 diff。除非用户要求，不提交、不推送、不更新或发布 PR。
