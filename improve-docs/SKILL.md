# 开发收尾与文档改进

检查本次工作是否产生了需要更新的说明或值得长期保留的知识，选择合适的位置沉淀。先展示具体建议，用户批准后再修改；没有可靠更新点时允许得出“无需更新”。

## 确定范围与证据

- 用户指定范围时遵守该边界；否则根据当前可见对话和实际改动确定本次任务，检查涉及的项目文档、适用的各级 `AGENTS.md`，以及实际使用、尝试使用或明确暴露问题的相关 skill。仅出现在技能列表或被提及不构成检查理由。
- 先读取适用的仓库指令，结合暂存、未暂存和相关新文件定位本次改动；任务已经提交时按需查看相关提交。区分本次任务与已有无关改动，不因工作区干净就认定无需更新。
- 从已知入口和涉及目录定向查找，读取相关文档、作用域覆盖这些目录的 `AGENTS.md` 和目标 skill 的必要资源。不遍历整个技能库，不扫描历史会话，不把开发收尾扩大为全库审计。
- 用实际实现、配置、测试和已确认的对话结论核对文档。无法定位目标、内容不可读或上下文不足时说明具体缺口，不猜测缺失事实。

## 判断是否需要沉淀

- 检查现有说明是否与实现一致，重点关注本次改变的使用方式、接口与数据契约、错误行为、兼容性要求、操作流程，以及后续开发需要遵守的约束。
- 区分已验证事实、用户明确的长期要求、待确认建议和临时处理。保留适用条件，不把一次性解决方案、单次成功或尚未验证的推测升级为通用规则。
- 新契约或约定应能说明依据、适用范围和对后续工作的实际影响。尚有实质性选择未确定时，明确列出待确认点，不作为既定事实写入；用户确认后再提供可审批的具体文本。
- 先判断问题是否已有规则覆盖。已有内容充分但执行时未遵守，不靠重复添加规则修复；实现和已确认契约冲突时指出差异，不擅自改写契约来迁就实现，也不顺带修改代码。

## 选择落点

- 项目行为、接口、使用和维护说明进入项目现有的权威文档；面向 agent 的项目操作约束进入作用域最小且合适的 `AGENTS.md`；可在该技能适用场景中复用的流程或经验进入相关 skill。
- 优先整合、替换或删除现有内容，在其他位置按需引用，避免多个文件维护同一规则。检查上下级指令及相关文档是否冲突；局部要求不提升为全局约束，项目特有知识不写成通用 skill 规则。
- 现有结构无法合理承载时才建议新增文档或必要的目录级 `AGENTS.md`，并说明位置与入口链接。不为留痕新增对话存档、经验流水账或空泛章节。
- 更新相关 skill 可在本流程中提出建议并获批实施，不依赖调用其他改进技能。本流程不负责创建新的 skill；若发现该需求，单独说明。

## 提出建议并等待批准

逐项编号，给出：

1. **依据与问题**：本次对话或实际改动中的证据，以及现有内容缺失、过时或冲突之处。
2. **目标与位置**：文件、段落及适用范围；新增文档说明为何需要独立文件及如何被发现。
3. **具体修改**：拟新增、替换或删除的文字，或足以审批的精简 diff；新增文档展示拟落盘内容，入口链接一并列出。

每项建议应能单独批准，相互依赖的修改合并为一项。没有可靠更新点时简要说明无需更新及原因，不强凑建议。

提出建议后请用户批准全部或指定编号，并停止等待。批准前不修改任何文件，也不提前写草稿、补丁或经验记录。调用本 skill 或一般性地要求“直接改”，不替代对本轮具体建议的批准；用户已批准具体内容时不重复索要同一批准。仅讨论建议、要求解释或含糊回复不视为批准。

## 实施获批修改

- 只实施获批项，保留用户已有的无关改动。用户调整建议或提出新增内容时，先展示调整后的具体文本，实质变化的部分重新审批。
- 修改前重读目标文件；若相关内容已变化导致建议不再适用，先重新提出调整方案。无关变化不阻止已获批的修改。
- 保留不在获批范围内的规则、技能名称、调用策略和元数据，使对应引用和链接与修改一致。公开内容使用相对路径、环境变量或通用占位符，不落盘凭据、私人机器信息和原始运行日志。
- 文件不可写或操作被拒绝时说明具体限制，遵守环境权限机制，不另改副本并宣称原文件已更新。不自动提交、推送或发布。

## 验证与汇报

- 核对实际修改与获批内容一致，检查术语、契约、上下级指令、入口链接和示例，清除本次修改引入的重复与冲突。
- 仅改文字时做内容一致性检查，并按对应场景推演约定的适用范围。涉及 skill 时，可用则运行技能格式验证器；修改调用配置时检查 YAML 和策略一致性。只在相关命令或示例确有验证必要且权限允许时执行，不为文档更新默认运行全量测试或有外部副作用的操作。
- 汇报已完成的建议编号、修改文件、验证结果，以及待确认或受阻事项。区分静态检查、案例推演和实际执行，不把未执行的验证说成已通过。
